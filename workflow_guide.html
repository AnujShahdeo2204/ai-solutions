⚙️ 2. How to Process Your Data (Step-by-Step)

Let’s take the exact sample data you provided: Products.csv (P101 to P105) and Orders.json (1001 to 1005). Here is how you can process it right now:

1

Method A: Through the Web Pipeline UI

No Code Needed

Open http://localhost:5173 and click on the Pipeline tab in the sidebar:

  1. Under CSV Products: Click "Upload Products.csv" and select your CSV file (or leave empty to trigger baseline).
  2. Under JSON Orders: Click "Upload Orders.json" and select your JSON orders file.
  3. Under XML Shipments: Click "Upload Shipment.xml" for shipment records.
  4. Click the respective Ingest button. The live activity log will confirm row count and update the database counters immediately!
2

Method B: Via REST API / cURL / Postman

Developer Method

You can send the payload directly via HTTP POST in the request body or as a file upload: 

# Ingest Products CSV:
curl -X POST http://localhost:5000/api/ingest/csv \
  -H "Content-Type: text/csv" \
  -d "ProductID,ProductName,Category
P101,Laptop,Electronics
P102,Smartphone,Electronics
P103,Office Chair,Furniture
P104,Monitor,Electronics
P105,Backpack,Accessories"

# Ingest Orders JSON:
curl -X POST http://localhost:5000/api/ingest/json \
  -H "Content-Type: application/json" \
  -d '[{"order_id":"1001","customer":{"id":"C001","name":"Rahul Sharma"},"items":[{"product_id":"P101","qty":2,"price":500},{"product_id":"P102","qty":1,"price":1200}],"order_date":"2024-01-05"}]'
🔄 3. The Complete Data Processing Workflow (Behind the Scenes)

What happens under the hood when data is submitted? The backend executes a 5-stage transformation pipeline:

A

Stage 1: Multi-Format Parsing & Sanitization

json.service.js / csv.service.js / xml.service.js

Raw client inputs frequently contain quirks from CSV exports, spreadsheet quotes, or XML hierarchy differences:

  • JSON Sanitizer: Automatically detects and cleans double quotation escapes (e.g., ""orders"" → "orders") and strips UTF-8 BOM byte marks (\uFEFF).
  • CSV Parser: Strips outer boundary quotes from every record and normalizes varied column keys (ProductID / product_id).
  • XML Parser: Parses <shipments> and normalizes both single-item objects and arrays into uniform lists.
B

Stage 2: Live Currency Conversion & Rate Caching

currency.service.js

The engine calls the public Frankfurter Currency API to calculate real-time exchange rates (e.g., INR to EUR / USD):

Rate: 1 INR ≈ €0.0092 EUR (TTL: 1 hour cache with offline fallback)

Every line item and order is stored with both original currency (total_order_value) and converted currency (total_order_value_converted).

C

Stage 3: Relational Multi-Way Join & Delay Derivation

transformation.service.js

The core transformation engine indexes Products and Shipments into in-memory hash maps for O(1) lookups and performs a 3-way join:

Order ID Customer Product & Category Calculation (Qty × Price) Shipment & Delay Status
1001 Rahul Sharma (C001) Laptop (P101) [Electronics]
Smartphone (P102) [Electronics]		 2 × ₹500 = ₹1,000
1 × ₹1,200 = ₹1,200
Total: ₹2,200		 3 Days — Delivered (Delay: false)
1002 Priya Verma (C002) Office Chair (P103) [Furniture] 3 × ₹800 = ₹2,400
Total: ₹2,400		 7 Days — Delayed (Delay: true)
1003 Amit Kumar (C003) Laptop (P101) + Monitor (P104) 1 × ₹500 + 2 × ₹1,500
Total: ₹3,500		 2 Days — Delivered (Delay: false)

* Delay Rule: An order is flagged as delivery_delay = 1 if shipment status is explicitly "Delayed" OR delivery days exceed 5 days.

D

Stage 4: Atomic Relational Storage in SQLite

storage.service.js / database.js

Data is written into normalized relational tables inside an atomic SQLite transaction. If any row fails, the database automatically rolls back cleanly without partial corruption:

customers
id, name
products
product_id, name, category, price, stock
orders
order_id, customer_id, order_date, total_order_value, total_order_value_converted
shipments
shipment_id, order_id, delivery_days, status, delivery_delay
order_items
id, order_id, product_id, qty, price, item_value
E

Stage 5: Live Aggregation & Dashboard Presentation

React 19 / Recharts / Tailwind

The React frontend triggers parallel API requests (Promise.all) for instant rendering:

  • KPI Summary: Queries /api/analytics/summary for Total Orders, Revenue, Delayed Count, and Avg Order Value.
  • Revenue Trends: Queries /api/analytics/revenue and renders an interactive SVG Area chart.
  • Category Breakdown: Queries /api/analytics/categories and draws a vertical/horizontal Bar chart.
  • Delivery Logistics: Queries /api/analytics/delivery and renders the Donut distribution chart.
  • Recent Orders: Queries /api/analytics/orders to populate searchable, sortable tables with drawer slide-outs.
